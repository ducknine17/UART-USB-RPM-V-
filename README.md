# Fardriver UART Monitor

Fardriver ND72680 컨트롤러를 USB-UART 케이블로 노트북에 연결했을 때, 브라우저에서 COM 포트를 직접 열어 RAW HEX 로그와 전압/RPM 후보 값을 보는 웹사이트입니다.

## 실행

PowerShell에서 이 폴더로 들어온 뒤 실행합니다.

```powershell
node server.js
```

그다음 Chrome 또는 Edge에서 엽니다.

```text
http://localhost:5173
```

`file://`로 `index.html`을 직접 열면 Web Serial API가 막힐 수 있습니다. 반드시 `localhost` 주소로 여는 쪽이 좋습니다.

## 사용 흐름

### Teensy 4.1로 진단하기

1. `teensy_uart_web_diagnostic/teensy_uart_web_diagnostic.ino`를 Arduino IDE에서 엽니다.
2. 실제 보드 `Teensy 4.1`, USB Type `Serial`, 해당 포트를 선택해 업로드합니다. 업로드는 기존 보드 프로그램을 대체합니다.
3. 시리얼 모니터를 닫고 사이트에서 `Teensy 4.1 진단`을 선택한 뒤 `장치 연결`을 누릅니다.
4. 컨트롤러 없이도 약 1초마다 틴시 상태 보고가 도착해야 합니다.
5. 전원을 끈 상태에서 검증된 컨트롤러 출력과 Teensy 0번(RX1), 통신 GND와 GND를 연결합니다. Teensy 1번(TX1), 컨트롤러 전원선은 연결하지 않습니다. Teensy는 USB로 전원을 공급합니다.
6. 컨트롤러의 출력 신호가 Teensy 3.3V 입력과 호환되는지 확인해야 합니다. 사양서의 TTL 표기만으로 3.3V임을 보장할 수 없습니다.
7. 정상 전원을 켜고 약 5초 뒤 진단 세 칸을 확인합니다. 문제가 있으면 `진단 결과 저장`으로 JSON 보고서를 저장합니다.

틴시 UART 속도는 스케치의 `UART_BAUD`(기본 19200, 8N1)입니다. 사이트의 USB 속도 선택으로 바뀌지 않습니다. 웹사이트와 스케치 모두 컨트롤러에 데이터를 송신하지 않습니다.

이전 `teensy_uart_receive_test` 스케치는 시리얼 모니터 전용입니다. 웹 진단에는 위의 **새 스케치**를 사용하세요. 새 스케치도 시리얼 모니터에서 JSON 문자로 볼 수 있습니다. `status`가 1초마다 출력되고 `rxRecent`는 직전 보고 구간 수신량, `rxTotal`은 부팅 이후 누적 수신량입니다. `data.hex`는 UART 원본의 16진수 표현입니다. 모니터와 사이트는 같은 포트를 동시에 열 수 없습니다.

### USB-UART 어댑터로 직접 수신하기

1. USB-UART 케이블을 노트북에 꽂습니다.
2. 장치 관리자에서 COM 포트가 잡혔는지 확인합니다.
3. 웹사이트에서 `USB-UART 직접 연결`을 선택하고, 통신 속도를 이전 성공 조건(기본값 `19200`)에 맞춥니다.
4. `장치 연결`을 누르고 해당 COM 포트를 선택합니다.
5. 원본 로그가 들어오면 `원본 Excel`, 해석 값이 잡히면 `RPM/전압 Excel`로 저장합니다.

## 현재 파서 기준

이 앱은 `jackhumbert/fardriver-controllers`의 역분석 자료를 기준으로 시작합니다.

- 상태 프레임은 보통 16바이트
- 시작 바이트는 `0xAA`
- 주소는 프레임의 `id`를 `flash_read_addr` 테이블로 변환
- `Addr E8`: 전압 `int16le(bytes 2-3) / 10`, 라인 전류 `int16le(bytes 6-7) / 4`
- `Addr E2`: RPM 후보 `uint16le(bytes 8-9)`

RPM은 실제 ND72680 로그와 공식 프로그램 값을 맞춰보면서 확정해야 합니다. 그래서 화면에도 `RPM 후보`라고 표시했습니다.

CRC가 맞는 16바이트 프레임만 해석 값에 반영합니다. CRC가 틀리면 한 바이트씩 이동하며 다음 프레임을 찾습니다. 정상 CRC는 알려진 프레임 형식과 일치한다는 뜻이며, 전압/RPM의 의미까지 검증한 것은 아닙니다. 값은 마지막 수신값이며, 갱신 중인지 진단 칸을 함께 확인하세요.

## 진단의 범위

- COM 포트 열림과 틴시의 새 상태 보고를 구분합니다. 상태 보고는 3.5초가 지나면 미확인으로 표시합니다.
- 5초 동안 새 UART 바이트 또는 CRC 정상 프레임이 없으면 최근 수신 없음/미확인으로 표시합니다.
- 전원, 단선, 핀 연결, 전압, 통신 속도, 시작 요청 필요 여부는 무수신 결과만으로 각각 특정할 수 없습니다.
- `usbDropped`는 스케치가 USB에 중계하지 못한 누적 바이트(사이트를 열기 전 포함)입니다. 하드웨어 UART에서 손실된 바이트까지 측정하는 값은 아닙니다.
- 데이터 메시지의 누적 바이트 위치가 이어지지 않으면 프레임 버퍼를 비웁니다. 상태 메시지에서 재부팅을 감지해도 이전 조각을 이어 붙이지 않습니다.
- `샘플 (실측 아님)`은 실제 수신과 분리되며 연결 중에는 사용할 수 없습니다. 실제 연결 시 이전 로그/샘플을 지웁니다.
- 진단 보고서에는 마지막 원본 로그 200행이 포함됩니다. 기록 정지 상태에서는 원본 로그가 추가되지 않지만 수신 진단은 계속됩니다.

## 소프트웨어 검증

```powershell
node --test --test-isolation=none tests/diagnostics.test.js
```

모의 데이터로 USB 메시지 분할, 수신 없음/정상/중단, 잘못된 CRC, 프레임 재동기화, 구형 스케치, 샘플 분리를 검증합니다. 실제 보드 업로드와 전기적 수신 검증은 별도입니다.
